# Архитектура Vectorize AI

## Общая схема

```
Браузер (React, TypeScript)
  ├─ загрузка: drag&drop / диалог / Ctrl+V / URL → probe в Web Worker → Pre-Crop (> 3 145 828 px)
  ├─ XHR multipart (реальный прогресс загрузки) ─────────────┐
  ├─ SSE /api/jobs/{id}/events (реальный прогресс стадий) ◄──┤
  └─ редактор: Vector Graph JSON → Path2D → OffscreenCanvas в Web Worker
                                                             │
FastAPI (backend/)                                           ▼
  ├─ SecurityMiddleware: CSP, CSRF-заголовок, rate limit, лимит тела
  ├─ роутеры: images, jobs, accounts/billing, meta, api v1
  ├─ Storage: storage/images/<token>/{source.bin, graph.json.gz, source.png, thumb.png, cache/}
  ├─ SQLAlchemy: users, sessions, api_keys, images, jobs, credit_transactions,
  │              subscriptions, payment_events, api_usage
  └─ JobManager (workers/): asyncio.Queue → N потребителей → ProcessPoolExecutor (spawn)
         ▲ прогресс: multiprocessing-очередь → поток-насос → подписчики SSE / ожидающие API
         └ отмена: общий словарь флагов, конвейер проверяет его при каждом отчёте о прогрессе

Воркер (workers/tasks.py) → vectorization_engine.vectorize() → graph.json.gz + превью
```

## Конвейер векторизации

| # | Стадия | Модуль | Суть |
|---|---|---|---|
| 1 | Декодирование | `image_processing.decode` | формат по сигнатуре (а не по расширению или MIME), сверка с Pillow, защита от «бомб», EXIF-поворот, ICC → sRGB, 16 бит, CMYK, палитры с прозрачностью → RGBA |
| 2 | Предобработка | `image_processing.preprocess` | уменьшение до `max_pixels` в premultiplied-пространстве, анализ (шум по Immerkær, ширина края, доля сглаженных краёв, блочность JPEG 8×8), bilateral-шумоподавление |
| 3 | Сегментация цветов | `image_processing.segmentation` | палитра по «плоским» пикселям (CIELAB + альфа, кластеризация «лидер» → взвешенный k-means → слияние близких → Ward до `max_colors`); граничные пиксели решаются как смесь двух цветов `c = a·ci + (1−a)·cj` (метка по `a ≥ 0,5`, то есть граница идёт по изолинии 50 % покрытия); второй проход добавляет необъяснимые, но пространственно связные цвета (тонкие линии); удаляются пятна и тонкие полосы «chroma bleed»; затем 4-связные регионы |
| 4 | Топология | `vectorization_engine.topology` | трещины между пикселями ориентированы «старший регион слева»; узлы — вершины степени ≥ 3 и углы кадра; цепочки трещин становятся интерфейсами; петли фигур собираются правилом «самый левый поворот» (4-связность) |
| 5 | Субпиксель | `vectorization_engine.subpixel` | покрытие сглаживания вдоль нормали трещины: `Σ coverage = t − x0` даёт положение края с точностью до долей пикселя; узлы ставятся в точку пересечения локальных прямых по МНК |
| 6 | Кривые | `geometry_engine.fitting`, `boundary` | фейринг (гауссово сглаживание), поиск углов на двух масштабах, классификация «острый / скруглённый» и восстановление острой вершины на пересечении опорных прямых; затем отрезки, дуги окружностей и G1-цепочки кубических Безье (взвешенный МНК Шнайдера, Ньютон–Рафсон, общий касательный вектор в точке разбиения); адаптивный допуск для слабых границ; учёт разрешённых типов кривых |
| 7 | Фигуры | `geometry_engine.shapes` + `recognition` | окружность, эллипс, прямоугольник (с выравниванием), скруглённый прямоугольник, треугольник (равнобедренный / равносторонний), четырёхугольник, правильная звезда; двусторонняя проверка Хаусдорфа; если у фигуры несколько соседей, узлы проецируются на идеальный контур, и каждый интерфейс получает свой участок |
| 8 | Симметрия | `geometry_engine.symmetry` + `recognition` | зеркальные оси (грубый перебор + уточнение), поворот порядка 2…12; симметризация усреднением по группе; повторяющиеся фигуры: сопоставление с поворотом и отражением, общий канонический контур, точные копии через аффинные преобразования |
| 9 | Финал | `curves.finalize_interfaces`, `graph.validate` | слияние коллинеарных отрезков, удаление вырожденных сегментов, проверка замкнутости петель и привязки к узлам, статистика |

Стадии 1–3 кэшируются на диске (`StageCache`, ключ — хэш параметров сегментации). Поэтому изменения геометрии, углов, фигур и симметрии в редакторе пересчитываются за доли секунды, и номера фигур не меняются.

## Vector Graph

```
Node      (id, x, y, border)
Interface (id, start, end, left, right, segments[], closed, border)   ← граница хранится ОДИН раз
Shape     (id, color, loops: [[(interface, reversed)…] outer, holes…], parent, parentHole, stackHoles, primitive, symmetry, repeat)
```

- Соседние фигуры ссылаются на один и тот же интерфейс, поэтому щели и наложения невозможны по построению. Тест `test_no_gaps_or_overlaps` проверяет, что каждый интерфейс использует ровно по одной петле с каждой стороны, а покрытие кадра равно 100 %.
- Прозрачные области тоже являются фигурами (`transparent=True`). Это даёт полную иерархию вложенности: родитель — фигура, в дыре которой лежит фигура; соседи по внешним петлям — «братья».
- `stackHoles`: дыры, которые нельзя закрасить в режиме «stacked», потому что внутри есть прозрачность. Тот же алгоритм повторён на клиенте (`deriveRenderState`), чтобы удаление регионов сразу отображалось правильно.
- Сегменты: `L`, `Q`, `C`, `A` (окружность: центр, радиус, начальный угол, знаковый размах), `E` (эллипс). Углы считаются в системе с осью y вниз, как в canvas.

## Редактирование

`EditState` (палитра: замена, добавление, удаление, слияние цветов; регионы: перекраска, удаление, фон, слияние) хранится на сервере и сохраняется с задержкой. История undo/redo (100 шагов) живёт на клиенте. Отрисовка применяет правки мгновенно. При экспорте `apply_edits` выполняет настоящее геометрическое объединение: общие интерфейсы удаляются, петли пересобираются, соседние фигуры одного цвета сливаются.

## Экспорт

| Формат | Реализация |
|---|---|
| SVG 1.0 / 1.1 / Tiny 1.2 | свои пути (в Tiny 1.2 дуги переводятся в Безье), нативные `circle`/`ellipse`/`rect`/`polygon` для распознанных фигур, cut-outs или stacked, группировка none / color / parent / layer, заливка, обводка фигур или обводка рёбер, gap filler, физический размер (px/pt/in/cm/mm + DPI) |
| PDF 1.4 | собственный писатель: FlateDecode, xref, ExtGState для полупрозрачности, `f*` (even-odd) |
| EPS | EPSF-3.0 / Language Level 3, DSC-комментарии, строки короче 255 символов; полупрозрачность сводится к белому фону (в PostScript нет альфа-канала) |
| DXF (R2010, ezdxf) | `lines` — полилинии; `lines_arcs` — LWPOLYLINE с bulge, где Безье аппроксимируются дугами; `lines_arcs_splines` — дуги через bulge и точные B-SPLINE; слой и true color на каждый цвет |
| PNG | растеризация векторов (не исходника): маска покрытия по bbox с суперсэмплингом 4×4 и композитинг «over» в premultiplied-пространстве, до 52 Мп |

## Подключение нейросетей

`vectorization_engine/ml.py` определяет протоколы `SegmentationModel` (стадия 3) и `EdgeRefiner` (стадия 5), а также реестр. По умолчанию работают классические реализации. GPU-модель подключается регистрацией объекта или переменной `VZ_SEGMENTATION_MODEL=pkg.module:factory`. Остальные стадии от этого не меняются.

## Безопасность

- Формат файла проверяется по сигнатуре; лимиты: 30 МиБ, 33,5 Мп при загрузке, 3,1 Мп для обработки; защита Pillow от «бомб».
- Загрузка по URL: только http(s) и порты 80/443/8080/8443; все разрешённые IP должны быть глобальными (запрещены loopback, частные сети, link-local вместе с адресом метаданных облака, CGNAT, multicast, IPv4-mapped); соединение закрепляется на проверенном IP (Host и SNI — имя хоста), что защищает от DNS rebinding; до 3 редиректов, каждый проверяется заново; поток ограничен по размеру и времени.
- CSRF: изменяющие запросы с cookie-аутентификацией требуют заголовок `X-Requested-With`, cookie ставятся с `SameSite=Lax` и `HttpOnly`.
- Rate limiting (token bucket) отдельно для групп: аутентификация, загрузки, API, остальное.
- Заголовки CSP, nosniff, X-Frame-Options, Referrer-Policy, COOP; Swagger UI раздаётся с собственного сервера и подключается с nonce.
- Пароли хэшируются scrypt (N = 2¹⁵); секреты API-ключей и токены сессий хранятся только как SHA-256.
- Изображения доступны только владельцу (пользователю или анонимной cookie); токены 192-битные. Просроченные данные удаляет фоновая задача каждые 10 минут.
